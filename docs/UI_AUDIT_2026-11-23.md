# Responsive UI audit — 2026-11-23

Public website only. The Admin desks moved to their own repo (`../Admin`, decision I-1) and are not
covered here; the Admin dev server was running on 5173, so this audit ran the website on **5180**
with the emulator-only profile:

```powershell
$env:DEV_VARS_PROFILE='demo-preview'; $env:MOCK_PHOTOGRAPHER_EMAILS='photographer-a@sites.test'
node node_modules/vinext/dist/cli.js dev --port 5180 --host 127.0.0.1
```

Method: the in-app browser (Chromium) at 320, 375, 768, 910, 1000, 1024, 1150 and 1280 px wide, light and
dark themes, signed out and signed in as `photographer-a@sites.test`. A script measured document width
against the viewport, elements past the edges, text wider than its box, tap targets under 24 px and the
sticky header's height; screenshots confirmed what it flagged.

Pages walked: `/`, `/games`, `/games/<slug>` (aircraft-identifier, military-aircraft-identifier,
atc-match), `/plane-of-the-day`, `/about`, `/how-to-play`, `/get-the-app`, `/privacy`,
`/review-conditions`, `/sign-in`, a 404, and signed in: `/account`, `/play`, `/contribute`.

## Findings (highest impact first)

| # | Page(s) | Viewport | Steps | What goes wrong |
|---|---|---|---|---|
| 1 | Every page with the site header, signed in | 320–~400 px | Sign in, open any page | The header wraps to two rows (brand, then the buttons): the sticky header grows from 64 to **121 px** and eats a sixth of a phone screen. The signed-in account button is 58 px wide (icon + caret), which pushes the row past the width. At 320 px the row also wraps signed out on tight devices. |
| 2 | Account menu, signed in | 320 px | Fix 1 alone, then open the account menu | The menu is 290 px wide and anchored to the account button's right edge; with the button ~70 px from the right, its left edge lands off-screen. |
| 3 | Every page with the site header | 901–~1100 px (signed in), 901–~990 px (signed out) | Width 910 or 1000, look at the nav | "Plane of the Day" wraps to two or three lines (nav link 83–107 px tall), the desktop nav collides with the header buttons. Common on small laptops and iPad landscape. |
| 4 | `/plane-of-the-day` | 320 px | Scroll sideways | The page scrolls horizontally (document 347 px). The closing "Share Your Aviation Photography" button is `white-space: nowrap` and 326 px wide in a 280 px column. Any long `.btn` label does the same on narrow screens. |
| 5 | Footer, every page | all | Tap the footer links | Footer links are 20–22 px tall. They pass WCAG 2.5.8 by spacing, but are small for thumbs. |

**Status:** all five fixed — 1–3 in `ff73221` (account button square on phones, menu anchored to the header,
nav folds into the menu at 1200 px; re-measuring found #3 reached 1200 px with a long signed-in name), 4–5 in
`3fe1299`. Re-verified at the same viewports.

Checked and fine: no horizontal scroll on any other page at 320/375/768/1280 in either theme; images
scale; forms (sign-in, account) fit at 320; the mobile menu and account menu close on Escape, and
menu links are full page loads (`SiteLink` is a plain anchor), so tapping the current page also closes
the menu; the
homepage hero fade-in only looks stuck when the browser pane is hidden (animations pause in a
background page), not a site bug.

Not covered: the photographer upload form (`/contribute` shows "Photo submissions aren't open yet"
without the backend and Bunny), real iOS Safari / Android Chrome (Chromium emulation only), live
Google sign-in.
